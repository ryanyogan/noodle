# Drizzle on D1, with money operations as atomic batches

We use Drizzle ORM against Cloudflare D1. Prisma was considered first but rejected: its D1 adapter silently runs `$transaction` as independent queries, which is unsafe for money. D1 itself has no interactive transactions (no read-decide-write inside one transaction), so Drizzle's `db.transaction` is not used either. Instead, every money operation (Cover, Sweep, Goal funding, Match, Split) is expressed as appended rows — never read-modify-write of a balance — and when several rows must land together they are written in one `db.batch([...])`, which D1 executes atomically.

## Consequences

- Balances (Bucket left, Earmark amount, Free to Spend) are derived from appended rows, not stored and mutated; any cached projection is rebuildable.
- Invariants that need a read first (e.g. "can't Sweep more than is left") are checked before the batch and re-guarded inside it with conditional SQL (`INSERT ... SELECT ... WHERE`), so a concurrent write by the other Parent can't break them.
- Schema lives in TypeScript; migrations are generated by drizzle-kit and applied with `wrangler d1 migrations apply`.
